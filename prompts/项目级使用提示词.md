# PACT 项目级使用提示词

> 本文件覆盖 PRD → 联调验收的逐阶段提示词。
> **项目初始化不在此处**：唯一入口见 `prompts/项目初始化提示词.md`（从 `.pact/templates/` 复制模板 + 生成项目背景与 PRD 骨架，对话驱动）。

## 1. 项目初始化

```text
请读取项目根目录下的 PACT.md。
本项目采用 PACT：产品 AI 契约化交付流程。
请先确认当前任务属于哪个阶段，再读取对应目录文件。
在没有更新需求契约、UIUX 契约或 API 契约前，不要直接修改代码。
```

> 若项目尚未初始化（根目录无 PACT.md），先使用 `prompts/项目初始化提示词.md`，不要从这里开始。

## 2. PRD 到页面清单

```text
请读取 02-产品文档/ 中的 PRD，输出：
1. 页面清单
2. 用户流程
3. 核心业务流程
4. MVP 范围
5. 验收清单

输出文件：
- 02-产品文档/页面清单_v1.0.md
- 02-产品文档/用户流程_v1.0.md
- 02-产品文档/验收清单_v1.0.md
```

## 3. 页面设计契约

```text
请读取：
- 02-产品文档/
- 03-品牌设计/
- 根目录 DESIGN.md（如存在，Design Token 以其为准）

为每个核心页面生成页面设计契约，写入：
- 04-UIUX设计/页面设计契约_v1.0.md
- 04-UIUX设计/design-tokens.json
- 04-UIUX设计/组件规范_v1.0.md

要求：
1. 覆盖 loading、empty、error、success、disabled 状态。
2. 明确主操作、次操作、危险操作。
3. 明确表单校验、列表筛选、弹窗规则。
4. 明确 PC、移动端、小程序适配规则。
5. 不生成代码。
```

## 4. API 接口契约

```text
请读取：
- 02-产品文档/
- 04-UIUX设计/页面设计契约_v1.0.md

生成 API 接口契约，写入：
- 05-技术文档/API接口契约_v1.0.md
- 05-技术文档/openapi.yaml
- 05-技术文档/数据库设计_v1.0.md

要求：
1. 每个页面需要的数据必须有接口支撑。
2. 每个接口必须包含请求参数、返回字段、错误码、示例响应。
3. 字段命名必须前后端一致。
4. 接口必须支持页面的 loading、empty、error、success 状态。
```

## 5. 前端 Mock 原型

```text
请读取：
- 02-产品文档/
- 03-品牌设计/
- 04-UIUX设计/
- 05-技术文档/

在 06-项目编码/frontend/ 中生成前端页面，先接 Mock 数据。

要求：
1. 严格按照页面设计契约实现。
2. 所有颜色、字体、间距、圆角、阴影来自 Design Token。
3. 实现 loading、empty、error、success、disabled 状态。
4. 表单可校验，列表可搜索筛选分页，弹窗可确认取消。
5. 代码结构要方便后续切换真实 API。
```

## 6. 后端 API

```text
请读取：
- 05-技术文档/API接口契约_v1.0.md
- 05-技术文档/openapi.yaml
- 05-技术文档/数据库设计_v1.0.md

在 06-项目编码/backend/ 中实现后端 API。

要求：
1. 先实现 GET /healthz。
2. 统一响应格式为 { code, data, message }。
3. 字段命名与 API 契约一致。
4. 错误码与 API 契约一致。
5. 不要修改接口契约；如必须修改，先说明原因并更新 05-技术文档。
```

## 7. 联调验收

```text
请读取：
- 02-产品文档/验收清单_v1.0.md
- 04-UIUX设计/页面设计契约_v1.0.md
- 05-技术文档/API接口契约_v1.0.md

完成前后端联调，并输出：
- 05-技术文档/联调记录.md
- 04-UIUX设计/UIUX走查报告_v1.0.md

要求：
1. 先检查 /healthz。
2. 再把前端 Mock 切换为真实 API。
3. 按核心流程、异常流程、空数据、权限不足逐项测试。
4. 发现问题记录到联调记录，不要静默修改契约。
```
