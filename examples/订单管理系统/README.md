## 2. 页面清单示例

| 页面 | 页面目标 | 核心操作 |
|---|---|---|
| 订单列表 | 快速查找和处理订单 | 搜索、筛选、查看详情、修改状态 |
| 订单详情 | 查看订单完整信息和履约进度 | 修改状态、备注、返回列表 |
| 新建订单 | 创建一笔新订单 | 填写表单、提交、取消 |

## 3. 页面设计契约片段

### 订单列表

| 模块 | 规则 |
|---|---|
| 页面目标 | 让运营人员在 30 秒内找到目标订单并执行处理动作 |
| 主操作 | 新建订单 |
| 次操作 | 搜索、筛选、查看详情 |
| 危险操作 | 取消订单，需要二次确认 |
| empty | 显示“暂无订单”，提供“新建订单”按钮 |
| error | 显示失败原因，提供重试按钮 |
| loading | 表格区域展示骨架屏 |

## 4. API 契约片段

| 接口 | 说明 | 对应页面 |
|---|---|---|
| `GET /api/orders` | 查询订单列表 | 订单列表 |
| `GET /api/orders/{id}` | 查询订单详情 | 订单详情 |
| `POST /api/orders` | 新建订单 | 新建订单 |
| `PUT /api/orders/{id}/status` | 修改订单状态 | 订单详情 |

## 5. 开发顺序

1. 先用 Mock 数据实现订单列表、新建订单、订单详情。
2. Mock 流程跑通后，实现 `/healthz`。
3. 后端按 API 契约实现订单接口。
4. 前端把 Mock 数据源切换为真实 API。
5. 按验收清单测试成功、空数据、错误、权限不足等场景。
