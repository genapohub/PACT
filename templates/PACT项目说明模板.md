# PACT 项目说明

> 本项目采用 PACT：产品 AI 契约化交付流程。  
> AI 参与本项目开发时，必须先阅读本文件，再根据任务阶段读取对应目录。
>
> 本文件由 agent 在项目初始化时从 `.pact/templates/PACT项目说明模板.md` 复制而来；
> 规范更新：`git -C .pact pull`。PACT 完整流程见 `.pact/README.md`。

## 1. 项目目录

```text
项目根目录/
├── 01-竞品分析/
├── 02-产品文档/
├── 03-技术文档/
├── 04-品牌设计/
├── 05-UIUX设计/
├── 06-项目编码/
├── 07-测试用例/
└── 08-其它文档/
```

## 2. 目录用途

| 目录 | 用途 | AI 使用规则 |
|---|---|---|
| `01-竞品分析/` | 竞品、差评、替代方案、市场参考 | 做需求和 UIUX 判断时读取 |
| `02-产品文档/` | PRD、页面清单、用户流程、验收清单 | 需求源，开发前必须读取 |
| `04-品牌设计/` | 品牌调性、色彩、字体、Logo、图标风格 | 生成 UIUX 契约和前端页面前读取 |
| `05-UIUX设计/` | 页面设计契约、Design Token、组件规范、走查报告 | 前端开发前必须读取 |
| `03-技术文档/` | API 契约、openapi、数据库设计、联调记录 | 前后端开发和联调前必须读取 |
| `06-项目编码/` | frontend、backend、miniapp 等代码 | 代码只写入这里 |
| `07-测试用例/` | 接口测试、全量测试、回归测试、UIUX 验收、截图证据 | 验证真实可用，不能用 Mock 代替 |
| `08-其它文档/` | 决策记录、交付说明、临时材料 | 不作为核心契约 |

## 3. AI 执行规则

### 3.1 先判断任务阶段

每次任务开始前，先判断属于哪个阶段：

| 阶段 | 应读取目录 | 应输出目录 |
|---|---|---|
| 需求结构化 | `01-竞品分析/`、`02-产品文档/` | `02-产品文档/` |
| UIUX 契约 | `02-产品文档/`、`04-品牌设计/` | `05-UIUX设计/` |
| API 契约 | `02-产品文档/`、`05-UIUX设计/` | `03-技术文档/` |
| 前端 Mock | `02-产品文档/`、`04-品牌设计/`、`05-UIUX设计/`、`03-技术文档/` | `06-项目编码/` |
| 后端 API | `03-技术文档/` | `06-项目编码/` |
| 联调验收 | `02-产品文档/`、`05-UIUX设计/`、`03-技术文档/`、`06-项目编码/` | `03-技术文档/`、`05-UIUX设计/`、`08-其它文档/` |

### 3.2 不允许跳过契约

禁止直接从 PRD 生成前端页面。

正确顺序：

```text
PRD
→ 页面清单 / 验收清单
→ 页面设计契约 / Design Token
→ API 接口契约
→ 前端 Mock
→ 后端 API
→ 联调验收
```

### 3.3 代码变更必须追溯到契约

如果开发中发现要改页面、字段、接口或流程：

| 变更 | 先改哪里 |
|---|---|
| 页面文案、按钮、状态 | `05-UIUX设计/` |
| 表单字段、列表筛选、页面数据 | `05-UIUX设计/` 和 `03-技术文档/` |
| API 字段、错误码、接口路径 | `03-技术文档/` |
| 核心业务流程 | `02-产品文档/` |

原则：

> 不能只改代码不改契约。

## 4. 前端开发规则

前端开发前必须读取：

- `02-产品文档/`
- `04-品牌设计/`
- `05-UIUX设计/`
- `03-技术文档/`

前端必须满足：

- 先接 Mock 数据跑通交互。
- 覆盖 loading、empty、error、success、disabled 状态。
- 表单有校验和错误提示。
- 列表有搜索、筛选、分页。
- 弹窗有确认、取消、关闭。
- 颜色、字体、间距、圆角、阴影来自 Design Token。
- 不使用 emoji 作为功能图标。
- 不使用 Lorem ipsum。

## 5. 后端开发规则

后端开发前必须读取：

- `03-技术文档/API接口契约_v1.0.md`
- `03-技术文档/openapi.yaml`
- `03-技术文档/数据库设计_v1.0.md`

后端必须满足：

- 先提供 `GET /healthz`。
- 统一响应格式为 `{ code, data, message }`。
- 字段命名与 API 契约一致。
- 错误码与 API 契约一致。
- 接口必须支持页面所需的全部状态。

## 6. 联调验收规则

联调前必须确认：

- `/healthz` 可用。
- 前端 Mock 流程已跑通。
- API 契约覆盖页面数据需求。
- 验收清单存在。

联调结果写入：

- `03-技术文档/联调记录.md`
- `05-UIUX设计/UIUX走查报告_v1.0.md`

- [ ] PRD 范围明确。

- [ ] API 接口契约完整。
- [ ] 前端 Mock 流程跑通。

- [ ] 前端切换真实 API 后核心流程跑通。
